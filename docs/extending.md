# Расширение

Система собрана так, чтобы четыре вещи менялись независимо: источник наблюдений,
регламент, речевые движки и формулировка реплик. Ниже — что именно править
в каждом случае.

## Подключить реальный модуль компьютерного зрения

Это главная запланированная замена. Точка подключения — интерфейс `Detector`
в [services/cv_adapter/detector.py](../services/cv_adapter/detector.py).

```python
class Detector(ABC):
    source_id: str

    @abstractmethod
    def stream(self) -> AsyncIterator[Observation | StreamHealth]: ...
```

Заготовка `RtspDetector` уже лежит рядом и намеренно не реализована — она
обозначает место в коде, а не только в документации. Реализация обязана:

1. подключаться к RTSP с переподключением при обрыве;
2. сбрасывать устаревшие кадры вместо накопления очереди;
3. выдавать `Observation` на каждую переменную из секции `observables` СОП;
4. проставлять `frame_ts` **временем кадра**, а не временем отправки;
5. слать `StreamHealth` при потере потока, засветке, обмерзании оптики.

Контракт — `contracts/observation.schema.json`. Проверить свой поток можно, не
поднимая систему: возьмите схему и валидируйте свои сообщения.

Что менять в остальной системе: **ничего**. `event_processor`,
`scenario_engine`, `voice_assistant`, `storage_api` и интерфейс инструктора
работают с потоком `cv.observations` и про источник не знают.

В docker-сборке достаточно подменить сервис `cv-adapter` в
`docker-compose.yml` на образ CV-команды, публикующий в тот же поток.

### Переходный период

Пока идёт разработка CV, полезно записать реальный поток и гонять его повторно.
Формат прогона (`configs/runs/*.yaml`) описывает состояния и шум, но никто не
мешает добавить реализацию `Detector`, читающую записанный `jsonl` с
наблюдениями. Это даст воспроизводимые прогоны на настоящих данных.

## Изменить или добавить сценарий

Регламент живёт в `configs/sop/*.yaml` — правки кода не требуется.

**Добавить шаг:**

```yaml
  - id: sample_check
    title: Отобрать пробу
    timeout_sec: 120
    expect:
      - variable: sample_valve
        equals: open
    requires: [pipe_bottom]
    phrases:
      instruction: Отберите пробу через пробоотборник.
      success: Проба отобрана.
```

**Добавить наблюдаемую переменную** — в секцию `observables`, после чего:

```bash
python -m tools.gen_schemas    # перегенерировать контракт для CV-команды
```

Новая переменная автоматически попадёт в перечисления JSON-схемы, в пульт
эмулятора и в индикаторы интерфейса инструктора.

**Сделать шаг критическим** — `critical: true` плюс `consequence` с описанием
последствия по регламенту. Тяжесть нарушения вычисляется от критичности
пропущенного шага, поэтому пометка немедленно меняет поведение: нарушение
станет останавливающим, а не предупреждающим.

**Добавить инвариант** — условие, которое должно держаться до конца сценария:

```yaml
invariants:
  - id: valve_stays_closed
    after_step: sample_check
    variable: sample_valve
    must_equal: closed
    severity: critical
    message: Пробоотборный кран остался открыт.
```

**Новый сценарий целиком** — новый файл в `configs/sop/`, путь к нему в
`configs/app.yaml` (`sop_path`). Валидация при загрузке проверит ссылки между
шагами и допустимость значений: ошибка в регламенте вылезет при старте.

## Заменить синтез речи

Интерфейс `TtsEngine` в [services/voice_assistant/tts.py](../services/voice_assistant/tts.py):

```python
class TtsEngine(ABC):
    name: str
    def synthesize(self, text: str) -> Synthesis: ...
    def available(self) -> bool: ...
```

Есть две реализации: `SileroTts` (локальный синтез, поставочный путь) и
`BrowserTts` (произносит вкладка инструктора, работает без зависимостей).
Подключить третью — добавить класс и ветку в `create_tts`, выбор задаётся
`voice.engine` в `configs/app.yaml`.

`available()` обязана возвращать `False`, если движок не сможет работать **без
обращения к сети**: тренажёр по п. 6.3 ТЗ живёт в изолированном контуре, и
попытка что-то скачать при старте означает зависший запуск. Скачивание моделей
выносится в отдельную команду — образец в `tools/fetch_silero.py`.

Отказ синтеза в рантайме не обрывает голосовой канал: сервис переключается на
браузерный синтез и продолжает работать.

## Заменить распознавание речи

Интерфейс `SttEngine` там же, в `stt.py`. Реализации: `FasterWhisperStt`
(локальное распознавание, когда микрофон у вычислителя) и `BrowserStt`
(распознаёт браузер, сюда приходит готовый текст).

Отдельно от распознавания стоит **сопоставление намерений** — функция
`match_intent`. Сейчас это ключевые слова, и для трёх команд это надёжнее
модели: список закрыт, слова заданы регламентом, а ошибка на фразе «к наливу
готов» стоит дороже, чем отказ понять нестандартную формулировку. Если
понадобится более гибкий разбор, менять надо только эту функцию — контракт
`VoiceCommand` останется прежним.

## Подключить языковую модель

Граница, которую нельзя переходить: **LLM объясняет и формулирует, но не выносит
вердикт.** Причины — в [architecture.md](architecture.md).

Места, куда она встаёт:

**Формулировка реплик.** Движок сейчас берёт текст из `phrases` в YAML. Чтобы
формулировать динамически — с учётом того, что человек ошибается третий раз
подряд, — нужен интерфейс `Responder` между вердиктом и `SpeakRequest`:

```python
class Responder(Protocol):
    def compose(self, verdict: Verdict, step: SopStep, history: list[Verdict]) -> str: ...
```

Вердикт к этому моменту уже принят, поэтому задержка LLM не попадает в тракт
решения — только в тракт озвучивания.

**Итоговый разбор сеанса.** После `SessionState.FINISHED` взять из `storage_api`
вердикты сеанса и получить связный разбор. Не в реальном времени, бюджет
задержки не затрагивается.

**RAG по регламентам.** Ответ на `VoiceIntent.HELP` сейчас берётся из
`phrases.hint`. Заменяется поиском по регламенту-источнику — это анализ
документов, а не действий, и он безопасен.

**Автопарсер PDF → YAML СОП.** Офлайн-инструмент, рантайма не касается.
Схема целевого формата уже есть — `contracts/sop.schema.json`.

## Сменить базу данных

Модели в `services/storage_api/models.py` не используют ни одного
SQLite-специфичного типа. Переход на PostgreSQL (п. 6.4 вопросника):

```bash
# configs/app.yaml
storage:
  url: postgresql+asyncpg://kft:kft@postgres:5432/kft01
```

```bash
pip install asyncpg
alembic upgrade head
```

Миграции написаны в batch-режиме, поэтому переносимы между диалектами.

## Заменить шину

Интерфейс `Bus` в [libs/bus/base.py](../libs/bus/base.py) — три метода:
`start`, `close`, `publish`, `subscribe`. Реализации: `RedisStreamBus` и
`InMemoryBus`. Для NATS или MQTT достаточно третьей реализации и ветки в
`bus_from_env()`.

Важное требование к реализации: `subscribe` обязана регистрировать подписку
**в момент вызова**, а не при первой итерации. Иначе всё опубликованное между
стартом сервиса и первым чтением теряется — гонка, которая проявляется ровно
на старте стенда и ровно один раз из десяти.
