# Эксплуатация

## Запуск

**Поставочный вариант.**

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps
```

Интерфейс инструктора — <http://localhost:8080>. Наружу смотрит только он;
остальные сервисы доступны внутри сети compose.

**Локальный вариант** (машина без Docker):

```bash
pip install -e .
python run_local.py --port 8080
```

## Проверка работоспособности

```bash
python -m tools.smoke                      # сквозной прогон через живой стенд
python -m tools.replay                     # приёмочные прогоны, без стенда
python -m tools.gen_schemas --check        # схемы не разошлись с кодом
python -m pytest                           # модульные и приёмочные тесты
```

Смоук-тест поднимает сеанс, гоняет сценарий, сверяет последовательность
вердиктов и проверяет задержку против норматива 2 с из п. 6.2 ТЗ.

## Конфигурация

Всё содержательное — в `configs/app.yaml`. В переменных окружения только то,
что зависит от способа развёртывания.

| Переменная | Смысл |
|---|---|
| `REDIS_URL` | задана — Redis Streams; пуста — шина в памяти |
| `KFT_CONFIG` | путь к конфигурации, по умолчанию `configs/app.yaml` |
| `DATABASE_URL` | строка подключения для Alembic |
| `UI_PORT` | порт интерфейса инструктора на хосте |
| `LOG_LEVEL` | `debug` \| `info` \| `warning` \| `error` |

Каталог `configs/` пробрасывается в контейнеры **только на чтение**: поправить
регламент или пороги на площадке можно без пересборки образа.

### Пороги сглаживания

Секция `smoothing` в `configs/app.yaml`. Значения стартовые — их калибровка на
реальных записях запланирована на этап интеграции: данные даёт CV-команда,
значения выставляет сценарная часть.

| Параметр | Смысл | Последствие ошибки |
|---|---|---|
| `confirm_window_sec` | окно принятия решения | больше — выше задержка; меньше — ложные срабатывания |
| `min_agreement` | доля согласных наблюдений | это и есть гашение дребезга |
| `min_confidence` | средняя уверенность | ниже — больше ложных подтверждений |
| `min_hold_sec` | минимальное удержание состояния | защита от пинг-понга |
| `unclear_after_sec` | сколько терпеть неопределённость | меньше — «не разобрал» на обычных переходах |
| `stale_after_sec` | молчание источника | меньше — ложные потери потока |

Порог `unclear_after_sec` обязан превышать самый долгий физический переход плюс
окно подтверждения. Для `pipe_position` это 4 с: опускание лебёдкой длится
секунды, и всё это время положение честно неопределённо.

### Бюджет задержки

Секция `latency_budget` — не настройка поведения, а зафиксированное соглашение
о том, какое звено сколько имеет права израсходовать. Фактические значения
видны в интерфейсе инструктора и по `GET /api/latency`.

## Журналы

```bash
docker compose logs -f scenario-engine
docker compose logs -f event-processor | grep "переменная"
```

Что искать при разборе:

* `переменная X: A -> B (согласие …, уверенность …, задержка окна … мс)` —
  подтверждение состояния сглаживанием;
* `шаг '…' нарушает предусловия […]` — блокировка;
* `нарушен инвариант '…'` — условие перестало соблюдаться посреди сценария;
* `шаг '…' засчитан с уверенностью … ниже порога` — сработала отсрочка;
* `прерывание: снято реплик из очереди` — критическое сообщение оборвало речь;
* `поток … : отброшено N сообщений при переполнении` — потребитель не успевает.

## База данных

SQLite по умолчанию, файл `data/kft01.sqlite3` в томе `kft-data`.

```bash
docker compose exec scenario-engine alembic upgrade head   # применить миграции
docker compose exec scenario-engine alembic current        # текущая ревизия
```

На стенде схема создаётся автоматически при старте; в поставке ею управляет
Alembic. Переход на PostgreSQL — смена `storage.url`, см.
[extending.md](extending.md).

### Что хранится

| Таблица | Содержимое | Срок по умолчанию |
|---|---|---|
| `sessions` | сеансы тренировок, строки отчёта п. 5.4 | 90 дней |
| `verdicts` | решения движка | вместе с сеансом |
| `state_changes` | подтверждённые смены состояния | 7 дней |
| `utterances` | реплики с замером сквозной задержки | вместе с сеансом |
| `observations` | сырой поток CV | 7 дней, **по умолчанию не пишется** |

Сырые наблюдения выключены сознательно: пятнадцать сообщений в секунду на
переменную растят базу быстрее, чем это оправдано. Включаются на время сбора
датасета для CV-команды:

```yaml
storage:
  store_observations: true
```

## Отчётность

Отчёт по форме п. 5.4 ТЗ — в интерфейсе инструктора и по HTTP:

```bash
curl "http://localhost:8080/api/report" | jq
curl -O "http://localhost:8080/api/report.csv"
```

CSV отдаётся с разделителем `;` и в UTF-8 с BOM — иначе Excel открывает
кириллицу нечитаемо, а отчёт смотрят именно в Excel.

## Сроки хранения и 152-ФЗ

Секция `privacy` в `configs/app.yaml` — **заготовки требований, а не их
реализация**. Это зафиксировано явно, чтобы на приёмке ответственность была
разделена:

| Флаг | Смысл | Кто исполняет |
|---|---|---|
| `consent_required` | требуется согласие на запись | организационная мера |
| `blur_faces_required` | требуется размытие лиц | технически — CV-модуль |
| `store_raw_video` | хранить ли сырое видео | CV-модуль |
| `video_ring_buffer_sec` | глубина кольцевого буфера | CV-модуль |

Размытие лиц технически выполняется там, где обрабатывается изображение, то есть
в модуле компьютерного зрения. Система в целом это требование **декларирует**;
исполнение — предмет отдельной договорённости с CV-командой.

Применение сроков хранения:

```bash
curl -X POST "http://localhost:8080/api/retention"
```

Вызывается по расписанию (планировщик задач Windows или cron). Сроки разные
для разных сущностей: сырые наблюдения живут неделю, отчёты о тренировках —
квартал.

## Типовые неисправности

**Стенд поднялся, но голоса нет.** Проверьте `GET /voice/state`. При
`tts_engine: browser` реплики произносит вкладка браузера — нужна незаглушенная
вкладка и разрешение на автовоспроизведение. Кнопка «Звук» в интерфейсе не
должна быть в положении «выкл».

**Долгий старт голосового сервиса.** Прогрев кэша идёт фоном и стенд не
задерживает. Если `cached_phrases` остаётся нулём — смотрите журнал
`voice-assistant`: скорее всего, модель Silero отсутствует и не может быть
загружена в изолированном контуре. Выполните `python -m tools.fetch_silero` на
машине с сетью либо переключите `voice.engine: browser`.

**Вердиктов нет, хотя состояние меняется.** Убедитесь, что сеанс запущен: вне
сеанса состояние отслеживается, но не оценивается. Затем проверьте журнал
`event-processor` — если подтверждений нет, пороги завышены для текущего
качества распознавания.

**Ложные «не разобрал» на обычных переходах.** Занижен `unclear_after_sec` для
соответствующей переменной. Он обязан превышать длительность физического
перехода плюс окно подтверждения.

**Задержка вышла за норматив.** `GET /api/latency` показывает разбивку. Если
велика часть «действие → вердикт» — дело в окне сглаживания. Если велика
«действие → голос» при нормальном вердикте — очередь реплик забита; проверьте,
не отключено ли прерывание инструкций.

**Сообщения теряются при старте в docker.** Потребители обязаны подписаться
раньше, чем источник начнёт публиковать. Порядок задан через `depends_on`;
если сервисы перезапускались вручную, поднимите `cv-adapter` последним.
