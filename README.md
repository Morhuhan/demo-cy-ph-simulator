# Сценарный модуль — киберфизический тренажёр

Сценарная, голосовая и интеграционная часть системы учебного контроля: модули
M06–M09 по архитектуре проекта.

Реализованный сценарий — КФТ-01, верхний налив ЛВЖ в вагон-цистерну: семь шагов
регламента, три из них с явными последствиями ошибки.

Второй сценарий — проверка СИЗ. Он сделан в этом же репозитории: движок
сценарно-агностичен, СОП описан данными в `configs/sop/`.

Стыковка с CV-модулем описана в
[docs/integration-cv.md](docs/integration-cv.md). Контракт событий пока **не
согласован**: фактический формат CV расходится с контрактом репозитория,
критично — отсутствие времени кадра.

## Что здесь работает, а что заглушено

Модуль компьютерного зрения разрабатывает отдельная команда. На его месте стоит
**эмулятор потока наблюдений** — он публикует в шину те же сообщения по тому же
контракту, что будет публиковать реальный CV-модуль.

| Часть | Состояние |
|---|---|
| Модуль компьютерного зрения | эмулятор (`services/cv_adapter`) |
| Приём событий реального CV | реализован (`services/cv_ingress`), контракт не согласован |
| Сглаживание потока наблюдений | работает |
| Сценарный движок, блокировки, три режима | работает |
| Голосовой ассистент, распознавание команд | работает |
| Журнал, отчёты, выгрузка CSV | работает |
| Интерфейс инструктора | работает |

Замена эмулятора на реальный детектор не затрагивает ничего выше по течению —
см. [docs/extending.md](docs/extending.md).

## Демонстрация проверки СИЗ

Сухой прогон на демонстрационных данных: реального CV-модуля и видеоматериалов
не требует, внешних зависимостей не имеет.

```bash
KFT_CONFIG=configs/app-ppe.yaml HOST=0.0.0.0 PORT=8080 python run_local.py
```

Открыть интерфейс инструктора, запустить занятие и выбрать прогон. Пять
сценариев показывают разные ситуации:

| Прогон | Что показывает |
|---|---|
| `ppe-clean` | проверка пройдена с первого предъявления |
| `ppe-no-helmet` | каска не надета: нарушение с указанием последствий |
| `ppe-helmet-removed` | каска снята во время работы — ловится инвариантом |
| `ppe-unclear` | система честно говорит «не разобрал», а не выдумывает вердикт |
| `ppe-stream-loss` | обрыв видеопотока не превращается в ошибку сотрудника |

Те же прогоны без интерфейса, в ускоренном модельном времени:

```bash
KFT_CONFIG=configs/app-ppe.yaml python -m tools.replay
```

Подключение реального CV-модуля — `configs/app-ppe-live.yaml` и
[docs/integration-cv.md](docs/integration-cv.md). Эмулятор при этом выключается:
два источника наблюдений по одной переменной будут спорить.

Стенд для CV-команды — в Docker: на Linux вместе с CV-модулем
(`docker-compose.full.yml`), на Windows и macOS — только стенд:

```bash
docker compose -f docker-compose.stand.yml up --build -d
```

Подробно — [docs/stand-docker.md](docs/stand-docker.md). Архив для передачи
собирает `python -m tools.pack_stand`.

## Выставочный экран

`/expo/` — стенд для выставки: посетитель перед камерой проходит упрощённый
верхний налив (5 этапов) на 3D-модели эстакады.

* каска — подтверждённые состояния CV-модуля через `/ws`, кадр с рамками —
  с самого модуля (`:8081/video`); снял каску — прохождение и 3D замирают;
* на каждом этапе выбор из трёх вариантов голосом, кнопкой или клавишей 1–3;
  при ошибке неверный узел подсвечивается в 3D красным;
* вопросы посетителя — ИИ-наставнику: языковая модель получает регламент
  КФТ-01 и состояние этапа (раздел `mentor`, ключ `AI_MENTOR_KEY`); без ключа
  экран отвечает по тексту СОП;
* речь распознаёт Whisper стенда (`/voice/listen?dry_run=true`), говорит
  наставник голосом Silero стенда (`/voice/say`, голос `eugene`) — по
  предложениям, чтобы первое звучало, пока синтезируются остальные; без
  Silero — голос браузера;
* итог прохождения — строкой в `data/expo-results.jsonl`, без имени.

```powershell
.\.local\start.ps1 -Expo
```

Ведущему: `H` — имитация каски (если CV недоступен), `C` — вернуть CV,
`R` — сброс, `V` — вид камеры (со стороны / от первого лица, там мышь и
WASD), `I` — пульт инструктора поверх экрана, пробел — удерживать и говорить.

Пульт инструктора — `/expo/instructor` (можно открыть на планшете): занятие,
режим «обучение / экзамен», вид камеры, проверка каски, «следующий
посетитель», ход прохождения и журнал. Занятия — в `static/expo/lessons.js`:
верхний налив по СОП КФТ-01 и обход эстакады с описаниями узлов из модели
заказчика; остальные шаги их демонстрации (слив, СУГ, вывод в/ц, аварийная
ситуация) видны на пульте, но закрыты до утверждённого регламента.

3D-сцена — 1 в 1 с исходным проектом UE4 «Наливочная» заказчика: расстановка
из карты уровня `L_Example.umap` с шаблонами BP, цвета из MI, логотип —
текстура материала `M_SIBUR`. Меши — из пака HTML5-сборки (UE Viewer).
Пересборка `static/expo/models` из исходников:

```bash
umodel_64 -path=<пак> -game=ue4.26 -export -gltf -out=<выгрузка> "/Game/Import/*"
python -m tools.ue4.expo_scene --content <Nalivochnaya/Content> --meshes <выгрузка>
```

Отладка сцены — `/expo/dev.html`.

## Быстрый старт

### Вариант 1 — одной командой в Docker

```bash
docker compose up --build
```

Открыть <http://localhost:8080>. Поднимаются шесть сервисов и Redis Streams.

### Вариант 2 — локально, без Docker

```bash
pip install -e .
python run_local.py
```

Открыть <http://127.0.0.1:8080>. Все сервисы живут в одном процессе, шина — в
памяти. Код сервисов при этом тот же самый: различается только точка сборки.

## Смоук-тест

Проверяет живую систему целиком — через HTTP и шину, а не в обход них.

```bash
python -m tools.smoke                        # прогон clean
python -m tools.smoke --run jitter-pipe      # проверка сглаживания
```

Тест запускает сеанс, гоняет скриптованный прогон, сверяет полученную
последовательность вердиктов с ожидаемой и проверяет задержку против норматива
2 с из п. 6.2 ТЗ.

## Приёмочные прогоны

Быстрая проверка без поднятия стенда — в ускоренном модельном времени:

```bash
python -m tools.replay              # все прогоны
python -m tools.replay clean -v     # один, с печатью вердиктов
```

Прогоны в `configs/runs/` помечены сценарием и загружаются только под свой СОП:
под КФТ-01 доступны шесть ниже, под СИЗ-01 — пять из раздела выше.

| Прогон | Что проверяет |
|---|---|
| `clean` | правильное выполнение всех семи шагов |
| `hatch-before-grounding` | критическая блокировка: люк без заземления |
| `report-without-bottom` | доклад о готовности при неопущенной трубе |
| `jitter-pipe` | дребезг распознавания не должен доходить до вердиктов |
| `stream-loss` | обрыв видеопотока не превращается в ошибку оператора |
| `grounding-lost` | заземление пропало посреди сценария |

У каждого прогона в YAML записана ожидаемая последовательность вердиктов —
это и есть приёмочный критерий из п. 5 вопросника Заказчика.

## Контракт для CV-команды

JSON-схемы в `contracts/` не пишутся руками — они порождаются из pydantic-моделей
и из машиночитаемого СОП, поэтому не могут разойтись с кодом:

```bash
python -m tools.gen_schemas          # сгенерировать
python -m tools.gen_schemas --check  # проверить актуальность
```

Главный файл — `contracts/observation.schema.json`. Это граница ответственности:
CV описывает, что видит; решения принимает сценарный движок.

## Голос

По умолчанию (`voice.engine: auto`) реплики произносит браузер инструктора —
работает сразу, без зависимостей. Серверный синтез Silero включается так:

```bash
pip install -e ".[voice]"
python -m tools.fetch_silero    # разовая загрузка модели, ~38 МБ
```

Модель качается отдельной командой намеренно: тренажёр по п. 6.3 ТЗ работает в
изолированном контуре, и загрузка чего-либо при подъёме стенда там означала бы
зависший запуск.

## Структура

```
configs/          СОП в YAML, пороги, прогоны эмулятора
configs/sop/      kft-01 (налив ЛВЖ), ppe-01 (проверка СИЗ)
contracts/        JSON Schema (генерируются)
libs/contracts/   pydantic-модели — единственный источник правды по обмену

services/         сервисы стенда, включая cv_ingress — приём событий CV

migrations/       Alembic
tests/            модульные и приёмочные тесты
docs/             техническая документация
_archive/         исходные видео, старые дампы и заменённые документы (вне git)
```
